- R-014 — Cerrado en B01-01 (`4bf3e58`): reemplazadas expectativas derivadas de la implementación por tabla independiente que cubre los 49 pares; semántica de tarea/intento/efecto y aprobaciones documentada en contrato.
- R-015 — Baja, mitigado en B02b-01: manifest fijado a Node 24.19.0 y guard de Node/SQLite efectivo antes del archivo objetivo. Node global antiguo 24.13.0 se rechaza; herramientas/gates usan el portátil verificado. No se cambia Node global ni se acredita nueva CI Linux.
- R-016 — Media: el lifecycle es validación pura de adyacencia. La ruta `uncertain -> failed -> queued` sólo es admisible tras reconciliación; `awaiting_approval -> succeeded` requiere evidencia y aprobación cuando corresponda. Los futuros servicios deben imponer esas precondiciones y conservar el historial de intentos. Los tests actuales no acreditan enforcement, permisos, reconciliación ni durabilidad.
- R-017 — Media, parcialmente mitigado B02b-02: correlación/idempotencia de B02b-01 conservadas; ahora se comprueba existencia, longitud y SHA-256 de blobs y coherencia del checkpoint con el log antes de aceptar almacenamiento/restores. No verifica veracidad de efectos declarados ni aprobación humana; los hashes detectan corrupción, no autentican contenido frente a dueño privilegiado.
- R-018 — Media, antes de logs/efectos: los diagnósticos de validación no interpolan datos de entrada, pero un mensaje de ejecución o blob válido puede contener secretos. El productor debe redactar antes de guardar/loguear; no hay redactor implementado en B01-02. La frontera de los parsers son datos JSON decodificados; no son un sandbox para getters/proxies u otros objetos JavaScript hostiles.
- R-019 / F-4 — Baja, cerrado: constantes exportadas del lifecycle mutables en runtime alteraban la validación global. Confirmado con tres tests rojos; congeladas lista, arrays y tabla mediante Object.freeze. Regresión y compatibilidad de tipos desde dist verdes, suite 62/62. Revisión APPROVE_WITH_FOLLOWUPS registrada; sin hallazgos bloqueantes restantes.
- R-020 — Alta, mitigado B02b-01: el adaptador exige Node 24.19.0/SQLite 3.53.3 reales antes de abrir el target; engines fijado. Rechaza el Node/SQLite antiguo afectado por WAL-reset y cualquier versión no evaluada. No elimina la necesidad de validar futuras actualizaciones de runtime; node:sqlite sigue release candidate.
- R-021 — Media, parcialmente mitigado F-5: SQL en worker, busy timeout 100 ms sin retry y presupuestos finitos configurables por apertura/cola/ejecución/backup/restore sustituyen watchdog fijo de 10 s. Cola no enviada expira con queue_timeout sin matar trabajo activo; pérdida de confirmación de mutación enviada conserva outcome_unknown. Una llamada nativa aún puede demorar la terminación física del worker; no hay cancelación dura de SQL ni exactly-once externo.
- R-022 — Media: SIGKILL verifica crash de proceso, no pérdida de alimentación/SO. FULL sigue sujeto a filesystem/hardware. B02b-02 ya prueba backup online/restores coherentes y checkpoints, sin sustituir activos; no acredita power loss, reconstrucción de efectos externos ni demo de runtime. WAL sólo en filesystem local; sin SLA derivado del benchmark.
- R-023 — Media, seguimiento P3: F-5 elimina replay por checkpoint y verificaciones repetidas mediante caché local SHA/bytes, pero startup/readEvents cargan el log completo e inventario/blobs/snapshots se materializan en memoria. No hay paginación, streaming, cuotas ni backpressure por volumen. 800 eventos/40 checkpoints probados no son SLA ni cubren tamaños arbitrarios; log sin firma/hash-chain privilegiada.
- R-024 — Media: el registro de escritor es sólo intraproceso y el path es configuración autorizada; no es liderazgo multiproceso ni sandbox de filesystem. No abrir varios control planes sobre la misma DB; SQLite serializa transacciones con BUSY como salvaguarda, sin protocolo de coordinación distribuida. Raíces/permisos de herramientas siguen en su fase.
- R-025 — Media, condición de seguridad: CAS/backup/restore requieren raíces privadas fuera de worktrees, con ancestros no modificables por actores no confiables. Se rechazan traversal, symlinks/junctions y reemplazos de directorios fijados, con no-follow y comprobación de identidad de fichero; POSIX comprueba dueño/no escritura de grupo/otros en raíces gestionadas. Windows depende de ACL privada del llamador. No se promete sandbox frente a un actor con permisos para cambiar ancestros durante un syscall; Node no ofrece openat portable. Las políticas futuras deben negar escritura de herramientas sobre raíces y ancestros de almacenamiento.
- R-026 — Media, seguimiento P3: no hay fsync portable de directorios en Windows. Se sincronizan bytes de archivos (snapshot con handle write-capable), se publican blobs sin overwrite y se valida al reabrir, pero no se afirma persistencia de metadatos de directorio tras power loss. 184 tests locales Windows x64; sin nuevo run Linux observado.
- R-027 — Media: un fallo entre CAS y SQL deja blobs huérfanos; backup/restore interrumpidos dejan directorios privados incompletos. Se ignoran/no aceptan y no se activan; no hay GC automático ni autenticación del manifest contra sustitución privilegiada. Limpieza, activación o reemplazo de datos reales necesitan autorización aparte; vigilar espacio antes de ampliar uso.
