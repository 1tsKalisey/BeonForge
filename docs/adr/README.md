# Architecture Decision Records

Create `NNNN-short-name.md` from this template. Use status `proposed`, `accepted`, `superseded` or `rejected`. Link a superseding ADR instead of erasing history.

```markdown
# ADR-NNNN — Title

- Date: YYYY-MM-DD
- Status: proposed
- Owners: BeonForge
- Related task: Fxx-yy

## Context

What problem and constraints require a decision?

## Options considered

What viable alternatives were evaluated and on which evidence?

## Decision

What is selected, and what is explicitly deferred?

## Consequences

How do we validate, observe, secure and reverse this choice?

## Revisit trigger

Which measured condition requires reconsideration?
```

The execution log in `docs/execution/decisions.md` tracks operational decisions as well as these ADRs. ADRs cover choices that shape multiple modules or phases.
